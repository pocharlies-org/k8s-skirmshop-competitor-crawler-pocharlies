## Root-cause discovered during implementation

leopard.es product pages use `<meta itemprop="name" content="...">` and
`<meta itemprop="price" content="...">` (not `<span>`). The old microdata extractor
called `get_text(strip=True)` on `<meta>` tags → empty string → product filtered out.
Fixed by preferring `element.get("content")` before `get_text()` for all microdata
property extractions.

## Residual Risks

1. **Homogeneous sample (all in_stock):** leopard.es homepage only shows in-stock items. No `out_of_stock` product found in the live crawl; that normalization path is covered by unit tests but not by a live sample. Codex may want to verify with a known out-of-stock URL in a future audit pass.
2. **Single catalog page (no BFS):** dry-run crawls only `source_url` from fingerprint (homepage). Products on deeper pages not reached. F2 is limited to what F1 discovers; BFS is a separate scope.
3. **Microdata nested `itemtype`:** leopard.es wraps `offers` inside a nested `itemtype="https://schema.org/Offer"`. BeautifulSoup `find()` is recursive so it crosses the boundary — this is correct for leopard.es but may over-reach on other sites with complex nested schemas. Low risk for F2 pilot scope.
4. **No out-of-stock live evidence from leopard.es:** `stock_method=visible` is only demonstrated for `in_stock` in the live sample. The rule "absence → unknown" is tested but not exercised against a real out-of-stock leopard.es page.
